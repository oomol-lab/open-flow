# 添加节点浮窗统一计划

状态：按钮岛浮窗第一版已实现，等待设计评审；完整入口统一尚未实施。

## 2026-09-13 预览范围

- 本轮仅替换按钮岛「添加节点」的打开方式，原侧栏、右键菜单和空画布入口保留。
- 通过 BlockLibrary 的独立 picker 展示模式复用现有目录服务，应用下区分触发器与操作。
- 内置节点双列，悬停或键盘聚焦显示说明；应用内和搜索结果单列显示用途。
- 节点创建沿用原按钮侧栏的创建回调与落点策略，成功后关闭浮窗。
- Lab `?story=node-picker-preview` 提供常开目录和按钮岛浮窗；使用生产内置选项、Trigger 定义与 Store，连接器接口使用确定性样例。
- 后续根据本版评审确定布局，再推进右键统一和移除侧栏节点库。

## 已确认方向

- 保留右键与显式「添加节点」按钮，统一打开同一套浮窗选择器。
- 浮窗在操作入口附近展开，负责搜索、浏览和选择节点；目录浏览在浮窗内部完成。
- 移除右侧栏的添加节点库，保留已选节点的配置侧栏。
- 后续可以在侧栏增加节点详情、文档与教程。本阶段不实现文档页面。
- 浮窗保留帮助用户选择节点的简短说明，不要求用户打开文档才能判断节点用途。

## 实施约束与待验证交互

- 浮窗屏幕位置与节点画布落点分别处理。右键位置及连线添加上下文在搜索、进入目录和返回时持续保留。
- 按钮添加的节点落点、位置提示、选择后的配置打开策略仍需具体设计。
- 复用现有目录数据和公共选择行为，保持配置中的 ActionPicker 等消费者可用；移除侧栏入口不等于删除共享 BlockLibrary 能力。
- 支持画布边缘避让、受可用空间约束的结果区滚动、键盘选择、Esc 关闭与焦点返回。
- 后续若从浮窗打开文档详情，应保留搜索与浏览状态。

## 面板设计讨论项

以下为候选建议，尚未作为最终设计确认：

- Provider Trigger 的中文命名与描述本地化方式。

## Provider Trigger 数据调查

- 前端 TriggerStore 调用 `listTriggerDefinitions()`，请求 Control API 的 `GET /v1/trigger-keys/catalog`。
- 响应为 `{ version: 1, definitions: TriggerKeySnapshot[] }`。默认服务端数据来自仓库内的 Provider Trigger 定义快照，服务构造允许替换定义集合。
- 快照已包含 `displayName`、`description`、`provider`、`type`、`configSchema`、`payloadSchema`，以及标识、版本等字段；integration 类型另有 endpoint 声明。
- 当前列表映射使用 `addNode.triggerNeedsConnection` 生成统一 description，没有展示定义原本的 description。原描述已参与搜索。
- 当前快照合同没有独立的教程正文、文档链接、示例或多语言描述字段。Schema 内部分字段包含说明，可支持配置和输出详情，但不等同于完整教程。
- 示例：Google Drive `changes_detected` 描述通过 `changes.watch` 通道接收变更通知；`on_file_change` 描述轮询指定文件夹内直接包含的文件或文件夹的新增、更新。

待讨论建议：列表次行展示用途与适用范围；通用连接说明放到分组提示或配置步骤，避免逐条占用说明位置。不要把当前无条件生成的连接要求误当作实时连接状态。

## 信息架构修订：节点与触发器页签

- 浮窗按用途分为「节点」「触发器」，不再把应用作为同级类型。
- 节点页展示内置节点（含注释），应用目录只进入连接器操作。
- 触发器页展示内置触发器，以及按应用分组的全部应用触发器；直接选择事件，无需进入应用目录。
- 搜索保持全局，结果按节点、触发器分组；清空搜索恢复原浏览页签。
- 保留紧凑尺寸、共享滚动条以及 LLM JSON 短名称。
