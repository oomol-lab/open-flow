# Flow 连接使用拆分计划

状态：已按确认范围实施并完成验证。Code 共享范围、其他消费者行为和旧数据清理范围均已确认。

本文记录目标行为、实施顺序和验收条件。实施时同步更新 `docs/architecture.md` 与
`docs/control/contracts/control-api.md`，替换其中与新行为冲突的合同。

## 1. 目标与已确认行为

将 Connector 节点使用连接与 Code 使用连接分开。连接服务继续管理账号授权，Flow 管理对连接的使用，发布固定该版本的使用关系。

- Connector 节点在属性面板选择当前用户有权使用的连接，不需要再到 Flow 页面勾选。
- 当前 Flow 的全部 Code 节点（包括 Subflow 中的 Code）共享一份允许使用的连接列表，通过独立页面手动管理；不能因其他节点选择了某账号就获得该账号的使用权限。
- Agent 的固定 Connector 工具、Trigger 和通知与 Connector 节点遵循同一规则：选中当前用户有权使用的连接即可，不依赖 Code 的共享列表；实际调用仍受对应 Action 或 proxy 权限约束。
- Flow 页面变为「连接使用」总览，展示账号、使用来源和状态，提供从当前草稿移除某账号使用的入口。
- Flow 总览不再负责统一添加授权；新增使用从对应节点或 Code 配置入口完成。
- 总览中的账号级「移除使用」影响该账号在当前草稿中的全部使用关系：清除 Connector、Agent 工具、Trigger 和通知中相关的连接选择，并从 Flow 的 Code 共享列表中移除该账号。
- 保留节点、代码、输入与连线。移除后不因账号仍为默认连接而自动重新选回。
- 不删除上游连接、不解除账号的 OAuth 或其他授权、不影响其他 Flow。
- Draft 修改不直接影响已发布版本。发布后，新版本采用新的连接使用配置；已经接受的 Run 使用其固定快照。
- 上游连接失效、账号授权撤回或权限策略变化仍由连接服务执行，可能影响已发布版本；这与编辑 Draft 是不同操作。

## 2. 界面与交互

| 位置                     | 内容                                               | 操作                                       |
| ------------------------ | -------------------------------------------------- | ------------------------------------------ |
| Connector 节点属性       | 当前 Action、已选账号、可用状态                    | 选择、更换、移除该节点的连接               |
| Code 独立配置页面        | 允许 Code 使用的连接及上游许可范围                 | 添加连接、移除使用                         |
| Draft「连接使用」总览    | 按 Provider 和账号汇总使用来源、节点与状态         | 定位节点、打开对应配置、从草稿移除账号使用 |
| 已发布版本的连接使用视图 | 发布时固定的使用关系，以及可区分的当前外部连接状态 | 只读查看                                   |

同一账号可在总览中合并展示，但 Connector、Agent 工具、Trigger、通知与 Code 共享使用的来源必须分别列出。Code 列表表达的是允许使用的连接，不声称静态分析得到了代码实际调用过的账号。

账号级移除前展示受影响的节点或 Code 使用范围，并明确说明：

> 从当前草稿移除此连接的使用？相关节点将不再使用此连接。账号连接、已发布版本和其他 Flow 不受影响。

添加 Connector 节点时可以选择符合当前 Action 权限的默认连接；没有默认连接、候选歧义、无可用连接时保留待配置状态。
刷新、重新打开草稿、移除使用后的状态同步不得触发自动回填。唯一候选是否自动选择沿用现有约定，实施时由行为测试明确。

## 3. 使用范围与迁移规则

### Code 使用范围：整个 Flow 共享

当前 Flow 的全部 Code 节点共享一份连接使用列表，由独立页面管理，不建立每个 Code 节点的连接许可副本。
节点入口打开同一份 Flow 配置；新增或复制 Code 节点自然使用该 Flow 已配置的列表，删除一个 Code 节点不删除共享列表。
Subflow 中的 Code 使用所属 Flow 的同一列表。总览以「Code 共享使用」标识此来源，不把动态调用推断为具体节点的静态引用。

### Agent、Trigger 与通知：按显式选择使用

Agent 的固定 Connector 工具、Poll、Integration 与通知纳入本次改造，按照各自显式配置使用连接，不借用 Code 的列表。
选择时验证操作者有权使用目标连接，调用时仍验证目标操作权限；「能选中就可以用」不扩大 Agent 的工具声明或 Trigger 的宿主能力。
Agent 临时代码计算不因此获得普通 Code 节点的 Connector 能力。
从 Flow 总览移除账号使用时，这些消费者也纳入受影响范围与一致性操作。

### 旧数据：仅清空旧 Draft 共享授权记录

已确认只清空旧 Draft 的共享授权记录，Code 的 Flow 级共享列表从空开始，由用户重新添加。
保留图中 Connector、Agent 工具、Trigger 和通知的连接选择，以及已有 Publication 和 Run 的固定记录。
不删除 Flow、Revision、节点、代码、上游连接或历史运行数据，也不把旧共享授权自动迁移为 Code 使用许可。

清理作为一次性、可识别版本且可重复执行的迁移完成，不能在每次启动或读取 Draft 时清空用户新添加的记录。
已有 Publication 和 Run 继续使用其固定授权身份；读取旧快照、恢复和 Rollback 的行为须由测试保护，不能通过清理 Draft 间接改变线上配置。
迁移脚本为 `0027_code_connection_usage.sql`；本次验证仅使用临时测试数据库，没有运行实际部署的数据清理。

## 4. 数据与权限边界

### 使用关系与上游资格分开

Connector、Agent 工具、Trigger 与通知的连接选择由各自配置表达。Code 的允许使用列表有独立的 Flow 级权威来源，不按 Code 节点复制。
部署继续负责解析和验证 opaque binding、Team、账号状态及上游许可，不把浏览器提交的 Connection ID 当作完整授权证明。

总览从节点配置与 Code 使用列表派生，不另存一份可独立修改的全局授权表。Provider、Action、Connection 保持独立的查询与缓存所有权。

### 固定执行身份

发布和 Run 准入固定当前连接使用关系及必要的部署授权引用。执行时使用固定来源，并由上游校验当前有效权限。
不能在每次执行时根据当前编辑者或部署 token 重新挑选任意可用 binding，替换发布时选定的身份。
若需要调整现有快照结构，应使用明确的版本与迁移规则，不能只新增一个调用标记绕开现有绑定检查。

宿主从实际 Task/invocation 判断调用属于 Connector 还是 Code；调用方脚本不能自行选择更宽的权限来源。
Code 即使知道另一个节点的 Connection ID，也不能使用未在其允许范围内的账号。
无需账号的 Action 与 implicit 部署沿用明确的部署合同，不制造不存在的账号授权，也不将其作为失败后的回退路径。

### Draft 修改一致性

「移除使用」跨越图配置和 Code 使用列表，必须由部署侧单个业务操作处理，校验预期 Revision 和使用配置版本。
不得用浏览器串行多个请求实现部分成功的删除。冲突时不覆盖其他编辑者的新配置，也不能误删期间新增的引用。
若既有存储分属不同边界，应先设计明确的一致性方案，再暴露此操作。
移除后应显示未发布变更；若所需连接未配置，检查与发布给出可定位的错误。

## 5. 实施步骤

### 第一步：确认合同并梳理消费者

- 按已确认的旧数据清理范围制定迁移；按第 3 节落实 Flow 级 Code 共享使用，以及节点复制、删除、撤销/重做和 Subflow 的一致性语义。
- 审核现有 ConnectorAccess、Draft binding、Publication、Run、Rollback、恢复、Trigger 和通知的使用路径。
- 定义连接使用查询、Code 添加/移除、账号级从草稿移除的返回形状、并发前提和错误语义。
- 更新架构与 Control API 合同；MCP/CLI 复用同一业务操作，不维护第二套权限逻辑。

### 第二步：实现数据和执行边界

- 在权威 owner 中分开节点使用与 Code 许可，并完成必要的迁移。
- 实现草稿账号级移除的一致性操作和变更通知。
- 更新发布、草稿测试运行、线上运行、Rollback 和恢复路径，使它们固定并使用正确的使用关系。
- 将 Connector、Agent 工具、Trigger 和通知的连接选择与 Code 手动添加解耦，保留上游资格和权限校验。
- 用后端行为测试先证明两类权限不互相传播，再接入界面。

### 第三步：Workbench 与工具接入

- Connector 自动配置只设置节点连接，不再调用 Code 使用列表的添加接口。
- 节点属性直接管理连接，不再把用户引导到全局勾选页面。
- 提供 Code 独立的「允许使用的连接」配置页面。
- 将 Flow「服务与授权」改为「连接使用」总览，展示使用来源、受影响节点和移除操作。
- 总览在 Draft 中可移除，在已发布版本中只读；正确显示未发布变化、处理中、失败与并发冲突。
- 更新受影响的 MCP/CLI 描述、命令行为、国际化文案和 Lab stories。

### 第四步：验收与交付

- 运行受影响的公共合同、服务端权限、生命周期和前端交互测试。
- 在 Lab 验证总览、Code 配置、Connector 选择，以及移除后的状态；必要时在正式 Workbench 验证发布边界。
- Open Flow 测试使用包目录下的 `bun run test`，提交前运行根目录 `bun run check`。
- 审查变更范围、迁移行为及遗留合同，再按用户后续指示提交与推送。

## 6. 核心验收场景

1. Flow 无 Code 许可时，添加有合法默认连接的 Connector 节点，节点可配置使用该连接，Code 使用列表仍为空。
2. Connector 使用账号 A、Code 仅允许账号 B：两者正常使用各自账号，Code 尝试 A 被拒绝。
3. 同一账号同时用于 Connector 与 Code，总览列出两个来源，但没有将两份使用关系合并为共同许可。
4. 从 Draft 总览移除该账号后，相关 Connector 选择和 Code 许可均移除；节点、代码与输入保留，刷新后不自动回填。
5. 移除仅在当前草稿生效，其他 Flow、旧 Publication、已接受 Run 和恢复执行使用各自固定记录。
6. 新版本发布后使用新配置；Rollback 恢复来源 Publication 的使用关系，不读取当前草稿列表。
7. 已知 Connection ID、伪造 binding、跨 Team 连接、越权 Action 和不允许的 proxy 请求不能绕过检查。
8. 上游连接断开或策略变化仍拒绝后续不合法调用，不回退到其他账号或更宽的权限。
9. 并发编辑与账号级移除发生冲突时，不出现只清除一部分使用关系的成功状态。
10. 新增、复制和 Subflow 中的 Code 均使用同一份 Flow 列表；删除单个 Code 不清除共享列表。
11. Code 列表为空时，Agent 固定工具、Trigger 和通知仍能使用其合法选中连接；它们的连接不向 Code 自动开放。
12. 总览账号级移除覆盖 Agent 工具、Trigger 与通知；旧数据升级只清空旧 Draft 共享授权记录，重复迁移不清除新配置，并保留节点连接选择、Publication 和 Run。
