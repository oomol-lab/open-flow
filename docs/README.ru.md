**Создавайте автоматизацию вместе с ИИ-агентом. Проверяйте, что именно будет выполняться.**

Open Flow — открытая платформа для рабочих процессов, которая сочетает скорость разработки с помощью ИИ и наглядность визуального графа. Попросите Codex, Claude Code или другого агента создать Flow, откройте его в Workbench и продолжайте совершенствовать тот же процесс вместе.

Объединяйте JavaScript, подключённые приложения, ИИ, ветвления и согласование с человеком на одном холсте. Проверяйте входные данные, следите за выполнением и выбирайте версию для публикации. Запускайте процессы в OOMOL Hosted или на собственной инфраструктуре.

[Открыть интерактивную демонстрацию](https://openflow.run) · [Использовать OOMOL Hosted](https://oomol.com) · [Развернуть через Docker](#выберите-среду-запуска)

![Процесс адаптации клиента в текущем Workbench: явные данные клиента, JavaScript, согласование и подпроцесс](assets/readme-workbench.png)

> [!IMPORTANT]
> Open Flow находится в стадии бета. Продукт и его версионируемые контракты продолжают развиваться.

## Агент создаёт. Вы управляете.

Опишите нужную работу:

> «Прочитай новые письма в поддержку, классифицируй обращения, подготовь ответы и запроси моё согласование перед отправкой».

Через [`oo flow`](https://github.com/oomol-lab/oo-cli) агент с доступом к терминалу может находить интеграции, создавать и редактировать узлы, проверять и запускать черновик, изучать результаты и публиковать по вашему запросу. Его изменения появляются в том же Workbench, где вы просматриваете граф и редактируете код. Отдельный проект, сгенерированный ИИ, не нужно преобразовывать или синхронизировать.

Server также предоставляет [MCP-инструменты редактирования и запуска](server/mcp.md) для совместимых клиентов. Оба интерфейса работают с Flow, ревизиями и запусками, сохранёнными в выбранном развёртывании.

Поручите агенту повторяющееся соединение узлов. Важные решения оставьте на виду.

## Каждый шаг открыт для проверки

Рабочий процесс должен оставаться понятным, даже когда переписка, в которой он появился, уже недоступна.

- **JavaScript для точной обработки.** Преобразуйте данные, форматируйте сообщения и пишите собственную логику в Code Tasks с именованными и типизированными входами и выходами.
- **Явные источники входных данных.** Панель свойств показывает, откуда берётся значение. Управляющие связи определяют, что выполнится дальше, а привязки входов определяют данные, которые получит каждый шаг.
- **Ветвления и переиспользуемые подпроцессы.** Направляйте работу с помощью условий и задавайте понятный интерфейс для повторяющейся логики.
- **Пояснения рядом с работой.** Объясняйте решения прямо на холсте, чтобы следующий участник понимал замысел.

## Задайте ИИ задачу и границы

Используйте LLM Tasks для классификации, извлечения данных и кратких сводок. Для работы с несколькими вызовами инструментов выбирайте Agent Tasks. Там, где нужно предсказуемое поведение, добавляйте обычный код, условия и согласование.

У Agent Task есть настроенная модель, явно объявленные инструменты и ограничения выполнения. Конфигурация инструментов определяет доступные модели действия, аккаунты и политику согласования. Можно потребовать одобрение человеком для вызова инструмента или поставить узел Approval перед следующим шагом рабочего процесса.

Узлы Approval и Wait сохраняют состояние ожидания в постоянном хранилище. После принятия решения работа продолжается без повторения уже завершённых шагов этого запуска.

## Следите за выполнением. Выбирайте, что публиковать.

Тестируйте черновик от выбранного триггера и наблюдайте за выполнением в Workbench. Просматривайте результаты узлов, журналы, ошибки и ожидающие согласования, не пытаясь восстановить весь ход работы по последнему сообщению. История сохраняет связь каждого запуска с использованной ревизией.

![Тестовый запуск процесса адаптации клиента ожидает согласования человеком в Workbench](assets/readme-approval.png)

Публикация создаёт версионированный снимок для автоматизации Live. Пока опубликованная версия работает, можно редактировать черновик, просматривать предыдущие Publications и при необходимости откатываться к более ранней версии.

Запускайте процессы вручную, по расписанию, через вебхук, поддерживаемые события сервисов или источники с периодическим опросом. Одно развёртывание управляет рабочим процессом, его версией Live и состоянием выполнения.

## Подключайте приложения без учётных данных в графе

Open Flow использует среду выполнения Connector, например [OpenConnector](https://github.com/oomol-lab/open-connector), для поиска и выполнения действий в Gmail, Slack, GitHub, Notion и других сервисах. Учётные данные аккаунтов остаются в Connector; рабочие процессы ссылаются на идентификаторы Connection.

OOMOL Hosted предоставляет управляемые OAuth-приложения для поддерживаемых интеграций. При самостоятельном размещении вы выбираете развёртывание Connector и управляете настройками сервисов и авторизацией аккаунтов. Логика процесса и доступ к аккаунтам остаются независимыми.

Полная настройка, включая авторизацию аккаунта и создание первого Flow, описана в руководстве [Open Flow с OpenConnector и CLI oo](server/self-hosted-stack/README.ru.md).

## Выберите среду запуска

| Вариант          | Чем управляете вы                                                                                  | Начало работы                                              |
| ---------------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| **OOMOL Hosted** | Рабочими процессами и подключёнными аккаунтами; развёртывание обслуживает OOMOL.                   | [Открыть OOMOL](https://oomol.com)                         |
| **Docker**       | Развёртыванием, хранилищем, резервными копиями, обновлениями и интеграциями.                       | Команды ниже                                               |
| **Fly.io**       | Приложением, постоянным томом, секретами, резервными копиями и обновлениями на инфраструктуре Fly. | [Руководство по развёртыванию](server/fly-io/README.ru.md) |

Для локального самостоятельного размещения установите Docker и OpenSSL, затем выполните:

```bash
git clone https://github.com/oomol-lab/open-flow.git
cd open-flow

export OPEN_FLOW_TOKEN="$(openssl rand -hex 32)"
docker build --file apps/server/Dockerfile --tag open-flow-server:dev .
docker run --rm \
  --publish 3000:3000 \
  --env OPEN_FLOW_TOKEN="$OPEN_FLOW_TOKEN" \
  --volume open-flow-data:/data/open-flow \
  open-flow-server:dev
```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000) и войдите с помощью `OPEN_FLOW_TOKEN`. Flow и история запусков хранятся в томе Docker. Тот же токен оператора используется для доступа через CLI и API.

Предпочитаете готовый образ? Следуйте [руководству по образам GHCR](server/docker-ghcr/README.ru.md) и на этапе бета выбирайте явный тег релиза. Тег `latest` предназначен для стабильных версий.

Для действий Connector и LLM Tasks нужно настроить соответствующие сервисы. Server не переключается на другого поставщика без вашего ведома. Перед открытием доступа из Интернета следуйте [руководству по развёртыванию](server/container-delivery.md) и [списку мер по усилению защиты](../SECURITY.md#hardening-your-deployment).

## Разрабатывайте на основе Open Flow

Open Flow распространяется по лицензии Apache-2.0. Репозиторий содержит контракты и среду выполнения рабочих процессов, Workbench, пакет команд CLI и Server для самостоятельного размещения. Версионируемый Control API позволяет клиентам не зависеть от реализации хранилища и выполнения в конкретном развёртывании.

Используйте версии Bun и Node.js, закреплённые в `.bun-version` и `.node-version`:

```bash
bun install --frozen-lockfile
bun run dev
```

Workbench для разработки доступен по адресу [http://localhost:5174](http://localhost:5174). При первом запуске токен оператора создаётся в `apps/server/.open-flow-dev/operator-token`. Настройка, проверки и Lab компонентов описаны в [CONTRIBUTING.md](../CONTRIBUTING.md).

## Связанные проекты

- [OpenConnector](https://github.com/oomol-lab/open-connector): шлюз коннекторов с открытым исходным
  кодом, который предоставляет каталог Provider, учётные данные и выполнение Action для узлов на базе
  Connector.
- [oo CLI](https://github.com/oomol-lab/oo-cli): локальный набор инструментов для агентов, в котором
  размещается команда `oo flow`, собранная из этого репозитория.
